# Type-Safety Audit: Runtime Validation Hotspots

> **Purpose:** catalogue runtime validation paths inside the headless and Material crates so we can replace guard-heavy code with typestate or compile-time builders that uphold invariants automatically. Each hotspot below cites the relevant implementation and calls out recommended follow-up work plus compatibility considerations.

## Headless state machines (`rustic-ui-headless`)

### Select state option bookkeeping
- **Runtime surface:** `SelectState::set_option_count`, `SelectState::set_option_disabled`, and `SelectState::is_option_enabled` clamp/ignore indices that do not exist instead of preventing invalid calls at compile time.【F:crates/rustic-ui-headless/src/select.rs†L225-L261】
- **Why it matters:** consumer renderers must remember to keep `option_count` in sync with the rendered collection or risk silent drops in analytics data and inconsistent `aria-activedescendant` wiring.
- **Recommendation:** introduce a typed option identifier (e.g., `SelectOptionId`) produced by a compile-time builder that is parameterized by the option collection. Downstream code would never see raw `usize` indices, eliminating the need for defensive bounds checks.
- **Follow-up issue draft:** _"Adopt typed option handles for `SelectState`"_ – build a new `SelectOptionSet` builder that accepts an iterator of options, materializes the `Vec<bool>` disabled mask internally, and returns strongly typed handles for selection/highlight operations. Ensure adapters still accept uncontrolled controlled toggles by implementing `From<SelectOptionId>` for `usize` behind a compatibility feature flag.

### List selection mode reconciliation
- **Runtime surface:** `ListState::new` and `ListState::set_item_count` repeatedly normalise selections, truncate overflow, and clamp highlights because callers may provide inconsistent `SelectionMode` + index sets at runtime.【F:crates/rustic-ui-headless/src/list.rs†L70-L189】
- **Why it matters:** the same state machine powers lists, tables, and menus. Runtime truncation can hide logical bugs (e.g., multiple defaults passed to a single-select list) and makes it hard to reason about automation telemetry.
- **Recommendation:** split `ListState` behind typestate variants (`ListState<Single>`, `ListState<Multiple>`, `ListState<None>`) generated by dedicated constructors so each variant enforces its invariants at compile time. Builders can also derive the initial highlighted index from the provided dataset, avoiding default-to-zero fallbacks for empty lists.
- **Follow-up issue draft:** _"Model `ListState` selection modes via typestate"_ – add mode-specific builders that accept typed selection collections (e.g., `SingleSelection`, `MultiSelection`). Provide `impl From` shims for the existing constructor signatures and gate the legacy API behind a `compat-selection-mode` feature until downstream adapters migrate.

### Pagination analytics tagging
- **Runtime surface:** `PaginationState::set_page_analytics_tag`, `PaginationState::set_page_count`, and `PaginationState::sync_current` all guard against out-of-range indices by early-returning or clamping.【F:crates/rustic-ui-headless/src/pagination.rs†L316-L340】
- **Why it matters:** analytics pipelines expect one tag per concrete page. If callers misconfigure the page count, tags silently drop, making telemetry gaps hard to detect during SSR snapshots.
- **Recommendation:** expose a `PaginationPlan` builder that captures the page collection (ids + optional analytics tags) up front and yields both the state machine and a typed iterator for renderers. This removes the need for mutating `page_tags` post-construction and allows compile-time validation in tests via const-evaluated arrays.
- **Follow-up issue draft:** _"Introduce `PaginationPlan` compile-time builder"_ – design a builder that requires the page count and optional tags at construction, verifies lengths eagerly, and emits deprecation warnings when `set_page_analytics_tag` is used under a temporary `pagination-legacy-config` flag.

## Material adapters (`rustic-ui-material`)

### Select option rendering contract
- **Runtime surface:** `option_attributes` indexes `props.options[index]` and trusts that the headless state's `option_count` matches the provided options vector.【F:crates/rustic-ui-material/src/select.rs†L303-L328】
- **Why it matters:** mismatched lengths trigger panics during SSR or hydration, yet the failure only appears at runtime because the API accepts raw `Vec<SelectOption>`. Automation IDs and analytics attributes also rely on the index alignment.
- **Recommendation:** add a `MaterialSelectBuilder` that consumes an iterator of `SelectOption` values and produces both the headless `SelectControlBuilder` and a sealed wrapper exposing only validated accessors. The wrapper can embed `SelectOptionId` from the headless follow-up to guarantee parity across state and rendering.
- **Follow-up issue draft:** _"Unify Material select props with headless builders"_ – create a builder that validates option counts, wires automation ids automatically, and offers feature-flagged shims for the current `SelectProps::new` constructor. Document migration steps in the Material select guide.

### Table column/row alignment
- **Runtime surface:** `row_markup` iterates over `props.columns` while calling `row.cells.get(col_index)` and then renders any surplus cells in an "extras" loop.【F:crates/rustic-ui-material/src/table.rs†L404-L434】
- **Why it matters:** downstream code can accidentally render mismatched columns without noticing, leading to malformed screen reader output and automation selectors that no longer line up with telemetry expectations.
- **Recommendation:** introduce a typed `TableSchema` builder that zips columns and rows at construction, emitting compile-time friendly diagnostics (via `Result` + `const` generics) when lengths diverge. Provide helpers that materialize automation ids from the schema rather than re-deriving them during rendering.
- **Follow-up issue draft:** _"Add `TableSchema` builder enforcing column-to-row parity"_ – accept column definitions and row iterators, validate lengths once, and expose iterators for SSR/hydration renderers. Offer a compatibility adapter that logs warnings when the legacy `TableProps::new` is used while downstream crates migrate.
