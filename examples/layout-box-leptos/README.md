# Leptos Responsive Box Layout Example

## Overview

This crate highlights how the RusticUI `Box` primitive can be used with Leptos
to assemble adaptive content panels. It encodes layout intent in a reusable
blueprint, documents hydration lifecycle hooks, and provides SSR output that
mirrors the CSR build byte-for-byte.

## Quick start

```bash
cd examples/layout-box-leptos
just bootstrap
```

The shared bootstrap script confirms Rust, `rustup`, WebAssembly targets, and
`trunk` are present before any compilation begins. CI environments can reuse the
same script to surface missing dependencies immediately.

## Common workflows

| Goal | Command | Notes |
| --- | --- | --- |
| Verify the crate | `just test` | Runs SSR-only tests first (`--no-default-features --features ssr`) and then the combined feature matrix via `cargo test --all-features`. |
| Lint & type-check | `just check` | Runs `cargo check` with every feature to catch layout or SSR regressions. |
| Produce a WASM bundle | `just build-csr` | Delegates to `trunk build --release` for deterministic Wasm artefacts. |
| Stream SSR markup | `just run-ssr` | Prints the full HTML document generated by the SSR renderer. |

## Required toolchains

- Rust stable and `rustup`
- `wasm32-unknown-unknown` target (installed automatically when missing)
- [`trunk`](https://trunkrs.dev/) for bundling WebAssembly
- [`just`](https://github.com/casey/just) for the developer/CI command surface

## SSR and hydration expectations

- `cargo run --features ssr --bin layout-box-leptos` emits the same document that
  production HTTP handlers would stream.
- CSR builds hydrate into the `#layout-box-root` element and record the hydration
  phase so monitors can assert that client-only effects stay gated until after
  the browser bootstraps.

## Tests

Tests assert:

- Responsive `Box` padding/width rules resolve to the expected breakpoint values
- SSR renderers retain automation markers and hydration annotations

Use `just test` (or `cargo test --manifest-path Cargo.toml --all-features`) prior
to submitting patches.

## CI integration

```bash
just bootstrap
just check
just test
```

The workspace-level `cargo test --workspace --all-features` also exercises these
scenarios, so adding new assertions keeps the entire stack honest.
